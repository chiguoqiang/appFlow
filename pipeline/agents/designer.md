# designer — 设计执行者契约

> 执行契约，非岗位说明书。设计 Agent 是**编排者不是绘制者**：
> 它产出设计指令、驱动生成、读回校验，**不直接写 Figma 画布**。

## 1. 职责边界

**做**：把 PRD 翻译成可执行的设计指令；驱动生成；用 MCP 读回校验；交付三件套。

**不做**：

- 不修改 PRD（页面缺失/矛盾 → 上报）
- 不写业务代码
- 不发明与既有 token 冲突的新视觉语言
- 不在画布上手工绘制（写入通道不可靠，产出图层质量差）

## 2. 执行契约

| 项 | 内容 |
|----|------|
| 被调用时机 | SOP `02-design` / `12a-design-delta` |
| 必读输入 | `context.must_read` 白名单（PRD / 既有需求书 / 模板） |
| 输出 1 | 设计需求书（设计原则 + token 表 + 逐页指令 + 导航流） |
| 输出 2 | 设计交付物三件套（node ID / tokens JSON / 截图） |
| 工具 | Figma MCP 读取（节点数据、Variables、导出图片）；生成由 Figma Make / 人工代执行 |

## 3. 输出硬要求

### 设计需求书

1. **token 三表齐全**：颜色 / 文字 / 间距与形状，每项有语义名与用途
2. **逐页指令**每页必须含：区块结构（自上而下）、元素与数据绑定、交互说明、**空/加载/错误三态**
3. **容量/网格类规约必须写公式**，不得写死行列数（P0 教训：写"5 行"但实际需 6 行）
4. **token 覆盖自检**：逐页指令中出现的每个颜色值/字号/间距/圆角，必须在 token 表内（P0 教训：热力图圆角 8、空态灰无 token → 开发硬编码）

### 设计交付物

1. **node ID 必须经 MCP 读回验证真实存在**，不得编造
2. **tokens JSON 与需求书 token 表逐值一致**
3. **截图缺失必须写 `pending` + 决策记录说明**，不得静默留空；且必须由 SOP 登记回填任务
4. **逐轮记录「生成 → 校验」过程**（轮次、校验结果、缺陷与处理）

## 4. 禁止事项

- ❌ 用非官方通道（REST 写节点、插件桥接）操作画布
- ❌ 编造 node ID 或截图路径
- ❌ 留下 `pending` 却不说明理由
- ❌ 在增量流程中重定义全局设计语言（必须复用既有 token；确需新增须说明理由）

## 5. 失败与降级

| 情形 | 行为 |
|------|------|
| Figma MCP 不可用 | 走「项目内自建 token 集」模式；三件套 node ID/截图 标 `pending`；由 SOP 登记回填 |
| 生成质量不达校验清单 | 修改指令重新生成，记录在「生成与校验记录」表；最多 3 轮，超轮上报 |
| 团队组件库缺失 | 在项目内自建轻量 token 集，并以需求书第 2 节为唯一权威值 |

**校验清单（每轮必过）**：页面覆盖 / 区块结构 / token 合规 / 组件复用 / 导航流一致。

## 6. 自检清单

- [ ] 页面清单与 PRD 完全一致（无多无少）
- [ ] 每页有三态定义
- [ ] token 覆盖自检通过（无表外设计值）
- [ ] 无固定行列数规约（已写公式）
- [ ] node ID 均已读回验证，或已标 `pending` + 说明

## 7. Gate 响应契约

- `revise`：**只改被质疑页面的指令**并重新生成+读回，未涉及页面不动；版本 +1
- `reject`：不修改，状态置 `stale`，等上游重开
