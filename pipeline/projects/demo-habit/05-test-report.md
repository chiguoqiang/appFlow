## 4. 缺陷清单

### BUG-01 · 首页进度 chip 出现「今日 1/0」（已打卡数 > 应打卡数）

| 项 | 内容 |
|---|---|
| 严重度 | **中** |
| 关联 | TC-02 / F-1 / US-1 |
| 复现步骤 | 1. 创建「每周 2 次」习惯<br>2. 本周内打卡 1 次（非今日）<br>3. 今日再打卡 1 次（本周累计 2 次 = 达标）<br>4. 回到首页看进度 chip |
| 预期 | chip 不出现 done > due；达标的每周型习惯今天打卡后，进度不应倒退（合理值：`今日 1/1` 或 `今日 1/0` 需显式设计为「今日目标已完成」） |
| 实际 | 显示 **「今日 1/0」** |
| 根因（代码定位） | `habit_stats.dart` `todayProgress()`：`due` 只统计 `isDueToday`，而 `isDueToday` 在「本周已达标」时返回 false；`done` 却单独统计今日是否打卡 → 两者口径不一致 |
| 修复建议 | `due` 改为「计入已打卡的今日目标」：`if (isDueToday || isCheckedToday) due++`；或进度语义改为「今日应完成 X，已完成 Y」并对 X=0 时展示「今日已达标」 |
| 状态 | 待修复 |

### BUG-02 · 从详情页删除习惯后停留在失效详情页

| 项 | 内容 |
|---|---|
| 严重度 | **高** |
| 关联 | TC-04 / F-2 / US-5 |
| 复现步骤 | 1. 首页点卡片 → 详情页<br>2. 点右上编辑 → 编辑页<br>3. 滚到底部点「删除习惯」→ 确认删除 |
| 预期 | 返回首页（空态或其他习惯列表） |
| 实际 | 停在详情页，页面显示「**习惯不存在或已被删除**」，用户需再手动返回一次；且此时页面无有效操作入口 |
| 根因（代码定位） | `edit_habit_page.dart` `_confirmDelete()` 只 `Navigator.pop()` 一次，回到的是已失效的 PG-03 |
| 修复建议 | 删除成功后 `Navigator.popUntil((route) => route.isFirst)`，或在 PG-03 检测到 `habit == null` 时自动 `pop` |
| 状态 | 待修复 |

### BUG-03 · FAB 阴影超出设计规范

| 项 | 内容 |
|---|---|
| 严重度 | 低 |
| 关联 | TC-12(UI) / 设计需求书第 3 节「无其他阴影」 |
| 复现步骤 | 观察 PG-01 右下角 FAB |
| 预期 | 设计明确「卡片：阴影 0 2 8 rgba(26,29,41,0.04)；无其他阴影」 |
| 实际 | `FloatingActionButton` 使用 Material 默认 elevation（6），阴影明显重于规范 |
| 修复建议 | `FloatingActionButton(elevation: 0, focusElevation: 0, hoverElevation: 0, highlightElevation: 0)`，或套用 `AppShape.cardShadow` |
| 状态 | 待修复 |

### BUG-04 · 前台跨天后数据不自动刷新

| 项 | 内容 |
|---|---|
| 严重度 | 低 |
| 关联 | US-3 验收标准「跨天后自动正确」 |
| 复现步骤 | 1. App 停留在首页不退出<br>2. 系统时间跨过 0 点<br>3. 观察日期头与统计 |
| 预期 | 跨天后日期头、今日进度、streak 自动更新 |
| 实际 | 页面不重建，仍显示前一天日期与进度（需切页/热重启才更新） |
| 根因（代码定位） | `clockProvider` 仅在 build 时读取一次，无午夜定时器、无 `WidgetsBindingObserver` 的 resume 刷新 |
| 修复建议 | App resume 时 `ref.invalidate(clockProvider)`，或状态层监听日期变化触发刷新 |
| 状态 | 待修复（也可降级为已知限制，由产品决定） |
